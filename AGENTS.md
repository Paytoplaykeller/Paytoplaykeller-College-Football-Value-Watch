# Recommendation integrity

Stephen treats leans as bets. Apply the same evidence requirements to BET, lean, strong lean, and rankings suggesting action. Never substitute conversational confidence for a completed own-model run.

Before actionable output, verify the exact code revision, successful run, event, market, line, timestamped executable quote, own-model forecast, adjusted probability, EV, availability checks, protective gates, and authorized stake. Missing evidence means PASS with the specific blocker. A research scan, successful upload, or passing unit tests is not a forecast or permission to recommend a wager. Never fabricate evidence or use test fixtures as live inputs.

Totals must remain PASS until a separately validated totals model and settlement-aware pipeline are operating. Keep existing injury, EV, bankroll, dispersion, privacy and ledger safeguards. Do not use third-party forecast disagreement as a gate.

Report scanner health separately from recommendation readiness. A stale, failed or empty run must be identified explicitly. Never claim a fix is live until the actual scheduled path has run successfully. Compare weekend results using frozen pregame forecasts and prices; never promise a repeat of a small-sample win rate.
